title: "Triage an Issue"
description: "Let your own coding agent investigate a ZLO problem and help file a good issue"

Triage lets your own coding agent investigate a ZLO problem. The agent reads the logs
and state of the machine, checks the ZLO source for the exact build that runs there,
finds known issues, and can help you write a good GitHub issue. It asks before it
applies a fix or posts anything.

## In the app

Press <kbd>⌘K</kbd> and choose **Triage an issue**. The new-thread screen opens with
the triage playbook linked in the message and asks "What went wrong?". Describe the
problem after the link, pick any model, and send. While you write, ZLO fetches the
source of the backend's build.

Triage runs on the computer the app is connected to; the line under the question
names it. If you switch to another computer before you send, the draft moves there:
that computer prepares its own session and the link changes. Send waits until the
link points at a session on the computer you are on; if that computer cannot prepare
one, the draft says so and points you at `zlo triage`. Any model works: the playbook
and the machine facts are part of your first message, so a model without file access
gets them too. The agent runs inside that ZLO backend, so it gives you any restart
steps and does not do them itself.

## In a terminal

If the app does not start, or triage does not work in the app, run this on the
machine with the problem:

```bash
zlo triage
```

The installer puts `zlo` on your `PATH`. If your terminal says `zlo` is not found
(open a new terminal after installing), run the copy inside the app instead:

```bash
~/Applications/ZLO.app/Contents/MacOS/zlo-backend triage
```

It starts Claude Code, Codex, or Antigravity in your terminal with the same
instructions. If more than one is installed, it asks which to use. You can also choose
explicitly:

```bash
zlo triage --agent antigravity
zlo triage --agent codex
```

Pass `--model <model-id>` to choose a model, or leave it out to use the CLI's default.
Antigravity needs Google's standalone `agy` CLI and its own sign-in.
`zlo triage` looks for each agent on your `PATH`, then in `~/.local/bin` and
`~/.claude/local`, where the installers put them even when they do not add that folder
to your `PATH`. If it starts one from there, it says so.
If none of the three is installed, `zlo triage` offers to install one in your terminal
and then starts it. Press Enter to skip; it then prints where it wrote the prompt so
you can paste it into any coding agent, and the install commands.

`zlo triage` reads no configuration and opens no database, so it works when the
backend will not start, and a setting it can work around (such as an unknown
`ZLO_PROFILE`) is listed in the session for the agent instead of stopping it. Each
session gets its own private folder, `~/.zlo/triage/<time>-<random>/` (`context.md`
with the machine facts, `triage-playbook.md` with the instructions), and the agent
fetches source into `~/.zlo/source/`. The in-app entry runs `git` for that fetch with
your git configuration, hooks, and credential helpers switched off, over https only.

## What the agent follows

The playbook is [`.github/triage/PLAYBOOK.md`](https://github.com/RiklloD/ZLO/blob/main/.github/triage/PLAYBOOK.md).
The agent checks for a newer copy on `main` first, never reads your secrets (the
WebUI token, the secrets master key, Keychain items) or any coding agent's sign-in
(Claude Code, Codex, Antigravity, Muse), redacts tokens and your home
folder from anything it quotes, prefers commenting on an existing issue over filing a
duplicate, and shows you the complete issue text before posting it with the
**Triage report** issue template.
